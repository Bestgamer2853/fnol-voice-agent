🧠 The Executive Pitch

"I built a production-grade Voice AI agent for Meridian Motor Insurance that automates First Notice of Loss (FNOL) claim intake. It replaces 20-minute call center hold times with a sub-800ms real-time conversational AI.

What makes the system unique is its Hybrid Orchestration architecture: Retell AI manages WebSockets and audio telephony, Gemini 2.5 Flash Lite extracts structured entities over Server-Sent Events (SSE), and an in-memory TypeScript Finite State Machine (FSM) strictly enforces deterministic business decisions — such as policy verification, conditional field tracking, and emergency medical escalations. Claims are logged asynchronously via a dual-write outbox pattern to Google Sheets and Resend transactional email."

01. 95% High-Probability Interview Questions

🔥 5 Questions You ARE Guaranteed to Get
  • Why use a hybrid FSM + LLM instead of a pure prompt-based agent?
  • How do you guarantee sub-second latency for voice conversation?
  • Walk me through your policy verification and fallback matching strategy.
  • How does non-blocking persistence prevent voice audio stuttering?
  • What happens when the LLM returns invalid or malformed JSON?
Q1: Why Hybrid Orchestration (FSM + LLM)?
In regulated insurance, pure LLMs cannot be trusted with business state. An LLM can hallucinate policy coverages, skip required FNOL fields, or miss medical emergency flags. Our hybrid design isolates the LLM to dynamic entity extraction and spoken text generation. All state transitions, validation guardrails, retry limits, and escalations are strictly owned by deterministic TypeScript code in ConversationManager.ts.
Q2: How do you enforce sub-800ms latency?
1. We stream audio & transcripts over raw WebSockets (via Retell AI).
2. We stream LLM responses token-by-token using Gemini's native SSE endpoint (streamGenerateContent?alt=sse).
3. We use a custom streaming JSON parser in server.ts that parses the responseToUser field as it arrives, forwarding text tokens to Retell TTS within ~350ms TTFT.
4. Persistence (Google Sheets & Resend Email) runs out-of-band without being awaited on the turn path.
Q3: How does policy verification work?
When policyNumber and callerName are present, verifyPolicy.ts executes: (1) Normalization (converting spoken numbers "one" to "1", uppercase, stripping dashes). (2) Exact lookup against policies.json. (3) If exact match fails, Levenshtein distance ≤ 2 fallback for STT misspellings. (4) Caller name verification using Jaro-Winkler string similarity with a threshold > 0.85.

05. Why Handbook — Engineering Decisions & Trade-offs

Why Express 5 over Fastify?
Express 5 offers mature promise error handling and robust middleware for static file serving and JSON parsing. While Fastify provides ~20% higher HTTP throughput, voice agents are bound by network latency and LLM streaming rather than HTTP routing CPU cycles.
Why raw `ws` over Socket.io?
Retell AI mandates standard WebSocket protocol (RFC 6455). Socket.io introduces custom framing, heartbeats, and room reconnection logic that break Retell's raw response_id and content_complete JSON protocol.
Why Gemini 2.5 Flash Lite over GPT-4o?
Flash Lite delivers ~350ms Time-To-First-Token (TTFT) via native SSE streaming at 90% lower cost ($0.075 / 1M input tokens vs $2.50). For voice AI, TTFT dictates perceived responsiveness.
Why `Promise.allSettled()` for Logging?
Promise.all() fails fast — if Google Sheets returns a 429 quota error, the local JSON log write would abort. Promise.allSettled() allows each logger (Local JSON, Google Sheets, Resend) to execute independently.

07. 5-Layer Anti-Hallucination & Compliance Engine

5 Guardrails Preventing LLM Hallucinations

1. JSON Schema Enforcement: Gemini is called with responseMimeType: 'application/json'. Output must strictly conform to our extraction schema.

2. Sanitization & Validation: validateClaimPatch() verifies types, trims strings, and validates format constraints (e.g. vehicle registration must be ≥ 4 alphanumeric characters).

3. Deterministic Policy Verification: verifyPolicy.ts executes exact, Levenshtein, and Jaro-Winkler matching against policies.json. The LLM has zero authority to verify a policy.

4. Deterministic State Transition Machine: Step transitions are governed by boolean logic in ConversationManager.ts, not LLM prompts.

5. Dual Extraction (LLM + Regex): extractFallbackClaimPatch() runs regex patterns on every turn to capture policy numbers, names, and booleans even if the LLM misses them.

10. Debugging Handbook & Failure Runbooks

Failure Runbook: Google Sheets 429 Quota Exceeded

Symptom: Terminal displays [GoogleSheetsClaimLogger] Error: 429 Rate Limit Exceeded.
Root Cause: Google Sheets API limits requests to 60 per minute per project.
Current Mitigation: MultiClaimLogger catches rejection via Promise.allSettled, writes the claim to data/outbox.json (Local Backup), and prevents process crash. Local JSON logging succeeds uninterrupted.
Recovery: Inspect data/outbox.json to view queued claims.

11. Outbox Verification & Codebase Fact-Check ⭐

🔍 Verification of Outbox Implementation

Question to Verify: Does the current codebase include an automated background retry worker replaying outbox.json back to Google Sheets?

Codebase Audit Findings (src/runtime.ts):

  • MultiClaimLogger runs Promise.allSettled([localLogger, sheetsLogger]).
  • If Google Sheets or any logger fails, MultiClaimLogger logs the failed record to outboxLogger (writing to data/outbox.json).
  • Fact Check: The repository does NOT contain a background cron worker or setInterval that automatically retries/replays records from outbox.json. It is a Local Backup / Persistence Guarantee.

Senior-Level Interview Response to Give:

"The current prototype guarantees that claim data is never lost by capturing failed writes to a local outbox file (outbox.json) whenever downstream services like Google Sheets hit a rate limit. In a production environment, I would attach a background worker (such as a BullMQ queue or cron task) to poll `outbox.json` and automatically replay failed writes with exponential backoff."

14. 100 Repository-Specific Interview Questions

Q1: What happens if Gemini returns markdown block fences around JSON?
extractJsonObject() in extractClaimData.ts uses regex /```(?:json)?\s*([\s\S]*?)\s*```/i to strip markdown fencing before invoking JSON.parse().
Q2: How does the mutex in LocalJsonClaimLogger work?
It uses a custom Promise chain mutex pattern (`this.promise = prevPromise.then(...)`) to serialize concurrent file read/write operations to data/claims.json, avoiding race conditions.
Q3: Why is Resend configured with an onboarding domain fallback?
Resend free accounts restrict recipient emails to the registered account owner. If a send fails due to recipient restriction, ResendNotificationService catches the error and retries with deiveeganaryan@gmail.com.
